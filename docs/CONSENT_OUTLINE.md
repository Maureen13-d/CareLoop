# Consent outline

This is an outline for a lawyer. It is not legal advice and it is not a consent form.

A Deaf signer and a patient would each need their own decision, in a language they use, before any recording or any follow-up that depends on it.

## Signer

- What will be recorded: a fixed phrase, not a conversation.
- Who can watch the raw recording, and that the raw file does not go into the git repository.
- That a pseudonym, not a legal name, is what the software stores.
- That withdrawing consent retires the clips. The software already does that when a staff member revokes the signer.
- That two Deaf reviewers and a different confirmer have to pass a clip before it can play.
- That a clinician still has to review the line before a pilot. Until then `pilot_enabled` stays false.

## Patient

- Kenyan Sign Language is a choice beside English and Kiswahili.
- The camera stays off. Answers are taps.
- "No, use taps" is the path this build ships. There is no camera consent screen because the camera is not used.
- A missed reply raises a person sooner than for a written check-in.
- The guide does not diagnose and does not say the person is fine.
- Stopping messages is still available.

Someone who cannot use the taps still gets a person. The software records that as a task, not as a reassurance.
